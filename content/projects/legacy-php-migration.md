## 상황

PHP5 시절에 만들어진 사이트를 PHP 8.4 호스팅으로 옮겼더니 **전 페이지가 500**이 되어버린 건입니다. 고객 요청은 명확했습니다 — "고급 기법 말고, 작동하게만, 단순하게."

## 진짜 원인부터

가장 까다로웠던 건 500의 **직접 원인**이었습니다. 알고 보니 `header("P3P : CP=...")`처럼 헤더 이름 뒤에 붙은 **공백 한 칸**이 범인이었습니다. PHP는 정상 종료하는데, 호스팅 앞단의 웹서버가 이 잘못된 헤더를 거부하며 500을 냈습니다. 그래서 "출력이 먼저 있는 페이지는 200, 없으면 500"이라는 기묘한 패턴이 나왔고, 이게 디버깅을 어렵게 했습니다.

## PHP8 비호환 전수 수정

그 위에 PHP 5→8 사이에 깨지는 것들을 전부 고쳤습니다:

- `mysql_*` 함수 제거 → `mysqli` 137곳 (인자 순서가 뒤바뀌어 주의 필요)
- `register_globals` 의존 코드 → 호환 레이어로 재현
- `ereg` 계열, 호출부 참조 전달, 따옴표 없는 배열 키, 없는 테이블 조회 시 치명적 오류가 되는 지점 등

핵심은 **기계적으로 안전하게 치환**하는 것이었습니다. 문자열 안에 든 유사 패턴까지 바꾸면 오히려 깨지므로, `token_get_all`로 코드 문맥만 골라 치환했습니다.

## 검증

호스팅 DB가 외부 접속을 막아 로컬 구동이 불가능해서, 서버에 격리 폴더를 올려 검증하고 끝나면 삭제하는 방식으로 진행했습니다. 최종 확인은 **기존 사이트와의 출력 diff** — 사용자 화면 10개가 바이트 단위까지 일치했고, 관리자 로그인부터 주요 화면까지 동작을 확인한 뒤 검증 파일을 모두 지웠습니다.
