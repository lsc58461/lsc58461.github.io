## 무엇을 맡고 있나

실제 사용자를 받는 서비스의 서버를 위임받아 운영하고 있습니다. 개발만 하고 넘기는 형태가 아니라, 자격 증명을 넘겨받아 장애가 나면 직접 들어가 원인을 찾고 고치는 역할입니다.

- **인프라 서버**: nginx 리버스 프록시(80/443), TLS 인증서, Redis, 테스트용 DB, ELK 로그 스택, 관리자 프론트엔드 컨테이너
- **애플리케이션 서버**: 백엔드·프론트엔드의 릴리스/테스트 컨테이너 4개 (프라이빗 레지스트리 이미지)
- **데이터베이스**: 클라우드 관리형 PostgreSQL (접속 정보는 컨테이너 환경변수로 주입)

## 인증서 만료 사고 — 원인은 갱신 방식이었다

관리자 도메인의 TLS 인증서가 만료돼 접속이 막힌 적이 있습니다. 표면적으로는 "자동 갱신이 안 됐다"였지만, 실제 원인은 **발급 방식과 서버 구성이 충돌**한 것이었습니다.

해당 도메인만 standalone 방식으로 발급돼 있었는데, 이 방식은 갱신할 때 80번 포트를 직접 점유해야 합니다. 그런데 그 포트는 이미 nginx가 쓰고 있어서, 갱신이 시도될 때마다 조용히 실패하고 있었습니다. 로그를 봐야만 보이는 종류의 실패라 만료되고 나서야 드러났습니다.

nginx와 협조하는 방식으로 인증 방법을 전환해 갱신하면서, **다음 갱신부터는 포트 충돌 없이 자동으로 처리**되도록 구성 자체를 바꿨습니다. 같은 문제가 남아 있는 다른 도메인도 함께 파악해 두었습니다.

## 운영하며 정리한 것들

- 서버에 `pg_dump`가 설치돼 있지 않아 백업이 막혔는데, PostgreSQL 공식 도커 이미지를 일회성으로 띄워 덤프/복구하는 경로를 만들어 두었습니다.
- Windows 환경에서 일반적인 SSH 클라이언트가 응답 없이 멈추는 문제가 있어, 스크립트로 접속·명령·결과 수집을 처리하는 방식으로 운영 절차를 바꿨습니다.
