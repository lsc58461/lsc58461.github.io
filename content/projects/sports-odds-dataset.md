## 무엇을 만들었나

역대 경기의 결과·배당·구매율을 한곳에 모아, 조건을 걸어 비슷한 사례를 찾는 서비스입니다. 데이터 복원으로 시작해 회원제 웹 서비스가 되었고, 지금은 안드로이드·iOS 앱을 만들고 있습니다. 수집부터 화면, 배포·운영까지 전부 맡고 있습니다.

## 1. 데이터 복원

공식 사이트가 화면으로만 보여주는 데이터라, 내부적으로 쓰는 조회 API를 분석해 계약을 복원했습니다. 세션 발급 → 회차별 조회의 흐름을 재현해 **로그인·캡차 없이 회차당 0.1~0.5초**로 전 회차를 수집했고, 경기 일정·배당·핸디캡·스코어·결과·구매율·배당 변경 이력까지 한 스키마로 적재했습니다. 특정 시점 이전은 원본 자체가 조회 불가라 복원이 불가능하다는 걸 실측으로 확인해, 계약 범위를 현실에 맞게 좁힌 것도 중요한 기여였습니다.

## 2. 검색 대시보드

종목별로 필터를 걸어 과거 사례를 탐색하는 UI입니다. 유사한 배당 조합을 무제한으로 정렬해 나열하고, 특정 조합의 출현 빈도를 일반/핸디캡 각각 통계로 보여줍니다. 전 회차 마스터는 엑셀로도 내보내고, 신규 회차는 자동으로 추가·검증됩니다.

## 3. 회원 서비스로 확장

- **소셜 로그인 3종**: 인증 라이브러리를 쓰지 않고 카카오·네이버·구글 OAuth를 직접 붙였습니다. 기존 서명 세션·감사 로그 체계를 그대로 쓰고, 첫 가입 때만 약관 동의 화면을 거칩니다.
- **계산기 4종**: 이번 회차 경기를 골라 배당 곱으로 계산하는 것 하나와, 복수 선택 조합 수 × 단가에 구매율 기반 예상 적중금을 보여주는 3종입니다. 이를 위해 수집 대상을 새로 추가했습니다.
- **해외 배당**: 해외 업체별 배당을 2013년 경기부터 모아, 경기마다 업체 평균 하나로 보여주는 수집기를 만들었습니다.
- **검색 노출**: 경기 상세 화면을 로그인 없이 볼 수 있게 열어 검색엔진에 잡히게 했습니다.

## 4. 무중단 배포 · 운영

실사용 트래픽을 받기 시작하면서 "배포할 때마다 끊기는 것"을 없애는 게 과제였습니다.

- **2레인 롤링**: `web-a`/`web-b` 두 레인을 두고 Caddy가 헬스체크로 새 레인이 정상일 때만 트래픽을 넘깁니다. sticky 세션으로 전환 중에도 사용자 세션이 끊기지 않습니다.
- **스키마 해시 스킵**: 매 배포마다 마이그레이션을 돌리지 않고, 스키마 해시를 비교해 실제 변경이 있을 때만 적용합니다.
- **분리 운영**: 실서버와 테스트 서버를 나눠 먼저 테스트 서버에서 확인하고, 야간 자동 백업 + 복구 시험으로 데이터 안전성을 확보했습니다.

## 5. 앱 (개발 중)

화면은 웹을 그대로 쓰고, 앱은 로그인·푸시·결제처럼 기기 기능이 필요한 부분을 맡는 하이브리드 구조입니다.

- **로그인 넘겨주기**: 구글은 웹뷰 안 로그인을 막습니다. 그래서 시스템 브라우저로 로그인하고 → 서버가 일회용 코드를 발급하고 → 앱이 그 코드를 세션으로 바꿔 웹뷰에 넣습니다(PKCE).
- **하단 탭**: iOS는 시스템 하단 탭을 쓰고, 안드로이드는 웹의 하단 메뉴를 그대로 씁니다.
- **푸시**: 경기마다가 아니라 회차당 한 번 보냅니다. 21~08시에는 야간 광고성 수신에 동의한 기기에만 보냅니다.

> 공개된 경기 결과·배당 기록을 정리해 보여주는 통계·레퍼런스 용도입니다.
